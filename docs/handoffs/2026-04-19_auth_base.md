## Decisiones técnicas

1. **JWT Bearer como paquete NuGet explícito en .NET 10.**
   `Microsoft.AspNetCore.Authentication.JwtBearer` fue removido del shared framework
   `Microsoft.AspNetCore.App` en .NET 10.0.3. Debe añadirse como NuGet explícito con versión `10.0.3`.

2. **`JwtBearerOptions` configuradas de forma lazy via `IOptions<AuthOptions>`.**
   Si se hubiera capturado el `SecretKey` en el lambda de `AddJwtBearer()` directamente
   desde `IConfiguration`, los tests de `WebApplicationFactory` habrían fallado porque
   la configuración se lee ANTES de que el factory pueda sobrescribirla.
   Solución: usar `services.AddOptions<JwtBearerOptions>(...).Configure<IOptions<AuthOptions>>(...)`,
   que resuelve `IOptions<AuthOptions>` desde el contenedor DI (después de que el
   contenedor esté completamente construido y las sobrescrituras aplicadas).

3. **Sin ASP.NET Core Identity completo.**
   `AppUser` es una entidad simple con `PasswordHash` como campo string.
   BCrypt se agregará cuando se implemente el login real.
   Justificación: mantiene la base simple y evita el andamiaje excesivo de Identity.

4. **Rol como string en `AppUser`.**
   No se creó una entidad `AppRole` separada. El rol es un campo `VARCHAR(50)` con constraint `CHECK`.
   Justificación: suficiente para la fase actual; se puede evolucionar a tabla de roles cuando haya casos de uso reales.

5. **`DevAuthEndpoints` solo en Development.**
   Verificado con `if (!env.IsDevelopment()) return;` antes de registrar endpoints.
   No hay protección adicional por contraseña o IP porque solo está disponible en entorno local.
   En producción, el handler retorna simplemente sin registrar ninguna ruta.

6. **Migración SQL manual en lugar de EF Core migrations.**
   Evita la dependencia del tool `dotnet-ef` y da mayor control sobre el SQL generado.
   Convención de naming: prefijo numérico de 3 dígitos (`001`, `002`, …).

## Problemas encontrados y resueltos

1. **`Microsoft.AspNetCore.Authentication.JwtBearer` no disponible en shared framework.**
   Error: `CS0234: JwtBearer no existe en Microsoft.AspNetCore.Authentication`.
   Causa: removido del shared framework en .NET 10.
   Solución: `dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer --version 10.0.3`.

2. **`IWebHostBuilder` no encontrado en el proyecto de tests.**
   Error: `CS0246: IWebHostBuilder no encontrado`.
   Causa: el proyecto de tests usa `Microsoft.NET.Sdk`, no `Microsoft.NET.Sdk.Web`, y no tiene implicit usings web.
   Solución: agregar `using Microsoft.AspNetCore.Hosting;` explícitamente.

3. **Todos los tests de auth fallando con 401.**
   Causa: `AuthExtensions.cs` capturaba `SecretKey` desde `IConfiguration` en el momento de registro de servicios, ANTES de que `WebApplicationFactory.ConfigureWebHost` aplicara las sobrescrituras de configuración.
   Solución: cambiar a `services.AddOptions<JwtBearerOptions>(...).Configure<IOptions<AuthOptions>>(...)` para leer `SecretKey` de forma lazy desde el contenedor DI.

## Limitaciones conocidas

- La migración SQL debe aplicarse manualmente: `infra/db/migrations/001_create_identity_tables.sql`.
- `appsettings.Development.json` contiene el SecretKey de desarrollo. En producción sobreescribir con `Auth__SecretKey` via variable de entorno.
- No hay endpoint de login real todavía (fuera del alcance de esta tarea).
- No hay hash de contraseñas todavía (BCrypt pendiente para cuando se implemente login).
- `Microsoft.AspNetCore.Mvc.Testing` se especificó originalmente como `10.0.0-preview.3.25172.1`. Considerar actualizar a la versión estable `10.0.3` en la próxima tarea.

## Recomendaciones para el siguiente agente

1. Leer el handoff anterior `2026-04-19_backend_base.md` además de este.
2. Para aplicar la migración: `psql -U tienda_online -d tienda_online -f infra/db/migrations/001_create_identity_tables.sql`.
3. Si se agrega login real, implementar en `Endpoints/AuthEndpoints.cs` y un servicio `IAuthService` en `Identity/Services/`.
4. Agregar BCrypt (`BCrypt.Net-Next` o similar) para hash de contraseñas antes de cualquier login real.
5. Considerar actualizar `Microsoft.AspNetCore.Mvc.Testing` de `10.0.0-preview.3.25172.1` a `10.0.3` (versión estable).
6. No avanzar todavía a catálogo, carrito, checkout, pagos reales ni FEL real.
7. Mantener el patrón lazy de `IOptions<T>` para cualquier configuración que deba ser sobreescribible en tests.
